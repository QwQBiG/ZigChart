# Architecture

[English](architecture.md) | [简体中文](architecture.zh-CN.md)

## Responsibilities

```text
MarketDataSource (browser host)
        | normalized batches
TypeScript bridge <---- browser input and frame scheduling
        | Wasm ABI v1
Zig engine: data + indicators + viewport + geometry
        | numeric frame batches
Canvas 2D renderer + DOM labels (browser host)
```

`core/engine.zig` has no browser dependency. It composes `averages.zig` for shared MA/EMA calculations and bounded additional instances, `oscillators.zig` for recursive RSI/MACD state, `bollinger.zig` for rolling price bands, `layout.zig` for shared pane geometry, and `price-scale.zig` for price transforms. `core/wasm.zig` exposes operations through a C-compatible ABI. `web/src/chart/bridge.ts` owns module creation, numeric marshaling, error conversion, and copying results. The feed adapts provider behavior; the renderer draws geometry supplied by Zig. The browser controls networking, events, device-pixel ratio, and animation scheduling.

Canvas 2D is the current rendering backend with no requirement to replace it. Browser-managed acceleration has no application switch. A future host can reuse the engine and provide drawing and input without introducing browser APIs into the core.

The browser source is divided by responsibility:

| Module | Contents |
| --- | --- |
| `main.ts`, `app/workspace.ts` | Small entry point and application composition |
| `app/chart-input.ts` | Plot pointer/wheel/keyboard routing, capture, gesture cancellation and listener cleanup |
| `chart/` | Wasm bridge/types, rendering/surface, time labels, shared numeric formatting, and price/time-axis input |
| `data/` | Canonical market contracts, immutable instrument catalog, sample provider, period rules and request/subscription lifecycle |
| `features/instruments/` | Validated symbol preference and per-symbol drawing/baseline state, including in-memory retention |
| `features/drawings/` | Drawing document/editor/rendering, object/style dialog, and independent `fibonacci-*` / `text-*` models, controls and renderers |
| `features/measure/` | Temporary two-anchor ruler state and presentation of copied core results |
| `features/appearance/` | Validated `model.ts` and the draft settings dialog in `panel.ts` |
| `features/analysis/` | Indicator `model.ts`, searchable `catalog.ts`, library/settings panels, chart legend, and indicator rendering |
| `features/export/` | Snapshot scene composition, bounded PNG raster/encoding, and preview/download lifecycle |
| `features/replay/` | Replay toolbar and selection/playback feedback, without owning the source clock |
| `features/series/` | Validated main-series preferences, type controls, and selection from the projected frame |
| `features/scales/`, `features/crosshair/` | Independent preferences and settings; scale feedback and frame-based crosshair resolution |
| `features/watchlist/` | Symbol picker, independent membership model and active-quote/sidebar presentation |
| `ui/` | Localization, control feedback, workspace layout, native fullscreen, themed dropdowns, and shared styles |

The workspace composes these modules; feature modules do not own data subscriptions or independent chart viewports.

`data/contracts.ts` owns `Bar`, `Instrument`, `HistoryPage`, `MarketDataSource`, `MarketReplay` and `ReplayState`. Data modules depend only on other data modules, including type dependencies. `chart/types.ts` and `data/replay.ts` retain type reexports for existing callers; new providers import the canonical contracts directly. This prevents provider code from depending on rendering or application assembly.

`app/chart-input.ts` owns plot interaction state and resolves the current core, frame and drawing editor through getters at event time. It delegates calculations to the existing core and feature controllers; it does not create another viewport or data session. Its cancellation and disposal release gestures and event listeners. Price/time-axis controllers remain in `chart/`; application composition remains in `app/workspace.ts`.

`npm run check:architecture` checks explicit relative runtime import/reexport cycles, confines all data imports to `data/`, and prevents reusable modules from importing `app/`. `main.ts` is the sole bootstrap exception. Entire type-only declarations do not create runtime edges; computed dynamic imports and future aliases require separate review. TypeScript compilation still owns module-resolution and type checks. Rendering may compose feature renderers; this dependency is intentional.

The Canvas series implementation belongs to ZigChart. Product layouts and documented chart behaviors are engineering references; the runtime does not embed another chart library or import upstream renderer source. All presentation types consume the same copied Zig frame rather than maintaining another chart model.

## Data and indicator state

Each engine retains at most 100,000 ordered bars. It validates a complete input batch before changing data or viewport state. Replacement, strict historical prepend, current-bar/new-bar upsert, and correction of loaded timestamps are distinct operations. Corrections atomically validate targets before recomputing the earliest changed suffix; they preserve time, locked ranges, pane weights and bar count. See [data-contract.md](data-contract.md) for exact ranges and revision behavior.

MA and EMA have independent integer periods from 1 to 500, initially 20. MA is an arithmetic mean of closes over its period. For EMA period `N`, the seed is the first complete `N`-bar mean and subsequent values use `alpha = 2 / (N + 1)`, independently of the MA period. Each is unavailable for its first `N - 1` bars and exported as `NaN`; renderers skip those values. Indicator outputs use floating-point units, preserving fractional means.

Six additional average slots reuse the same recurrence in `averages.zig`; each stores kind (disabled/MA/EMA) and period. A complete configuration batch is validated before mutation. Only changed active slots recalculate; unchanged configuration preserves locked ranges, while changed membership/parameters refit without moving time. Disabled slots skip updates. Corrections recalculate the changed suffix, prepends rebuild seeds, and snapshots retain configuration. Active values participate in automatic bounds and logarithmic eligibility using the common price transform.

The six retained result arrays reserve 4,800,000 bytes and the fixed frame buffer reserves 192,192 bytes at the 2,002-row maximum. No per-call allocation or memory growth is introduced. When the active mask is nonzero, disabled slots export NaN. With all six disabled, the frame buffer is stale and must not be read; the bridge omits its copy. The original MA/EMA arrays remain computed for ABI v1 inspection compatibility. This is a bounded extension, not an arbitrary indicator plugin system.

`configure_indicators(ma_period, ema_period, mask)` atomically validates periods and a 0–7 presence mask (MA = 1, EMA = 2, Volume = 4). All are absent by default. Changed periods recalculate only their affected indicator; changing a period or presence restores automatic vertical fitting while preserving the horizontal viewport. An identical configuration is a no-op. Only present overlays contribute to the automatic price range. An absent auxiliary pane uses no height; active panes share the released space. Frame rows and the 13-value metadata layout remain unchanged.

`core/bollinger.zig` owns one optional close-based Bollinger Bands study. For a full `N`-bar window, basis is the SMA, population variance is `sum((close - basis)^2) / N`, and upper/lower are `basis +/- multiplier * sqrt(variance)`. Period is an integer 1–500, multiplier is finite within 0.1–10, and defaults are 20/2 with the study disabled. The first `N - 1` rows are NaN; period 1 produces three equal values. Enabled bands contribute to shared price bounds and logarithmic eligibility; a nonpositive lower band can cause the documented regular fallback. BB is a price overlay, so configuration neither creates a pane nor changes maximization. Styles stay in the host and cannot alter calculation inputs.

The bounded moments tree has at most 512 leaves and merges centered means/variance rather than subtracting squared-price sums. This avoids the cancellation inherent in `E[x²] - E[x]²` for narrow spreads at large prices. Recalculation rebuilds the preceding window, then replaces each changed member; disabled BB skips calculations and unchanged configuration preserves locks. The bridge copies six row-aligned values `[basis, upper, lower, basisY, upperY, lowerY]`; a hidden price pane retains raw values with NaN coordinates. Existing ABI v1 rows and metadata are unchanged.

`configure_oscillators(rsi, fast, slow, signal, mask)` independently validates integer periods 1–500, `fast < slow`, and mask 0–3 (RSI = 1, MACD = 2) before mutation. Defaults are 14 and 12/26/9, all disabled. `oscillators.zig` skips disabled calculations; enabling or changing parameters recalculates the affected study. Identical configuration is a no-op. Changed configuration refits vertical ranges without moving time.

RSI seeds average gains and losses with the first `N` close changes, at bar index `N`. Subsequent averages use Wilder smoothing `(previous * (N - 1) + change) / N`. The result is `100 - 100 / (1 + gain / loss)`; both averages zero gives 50, only loss zero gives 100, and only gain zero gives 0. The first `N` bars are unavailable. RSI is dimensionless with a fixed 0–100 scale; editable reference levels are presentation only.

MACD subtracts the slow EMA from the fast EMA, each using its complete-period SMA seed. The first value is at `slow - 1`; signal EMA starts from the mean of its first `signal` valid MACD values at `slow + signal - 2`. Histogram equals MACD minus signal, without a factor of two. All three retain fractional price units. Unavailable values and coordinates are `NaN`. Revisions reuse the preceding recursive state; repeated updates of one bar never compound that bar twice. History prepends can change RSI/MACD seeds and visible outputs as well as MA/EMA.

A snapshot replacement or history prepend recalculates indicators from the earliest retained bar. Loading older history therefore changes the EMA seed and can change EMA values already visible; this is expected, not a revised market price. It can also fill previously unavailable MA/EMA values. A latest-bar replacement recomputes from that index using the preceding EMA, preventing repeated updates from compounding the same candle twice. Appends recompute only the changed suffix.

EMA recomputation sums the initial `N` closes only when the affected suffix includes its seed. A mature latest-bar revision uses the stored preceding EMA without repeating the seed sum. Drawing projection and pointer conversion request shared frame metadata without producing another batch of candle rows; their coordinate contract is unchanged.

## Coordinates and interaction

The viewport is a fractional starting bar index plus a span of candle slots. Its lower bound is 10; its upper bound is `clamp(plotWidth / 6, 10, 2000)`. The host calls `resize_plot(width)` with the current CSS plot width, excluding the price axis, before using geometry after a layout-width change. This keeps candle centers at least 6 CSS pixels apart for plot widths of at least 60 pixels; the 10-slot minimum still applies below that width. Bars have uniform logical spacing, including across timestamp gaps. The core uses this one horizontal mapping for candles, volume, indicator lines, and hit testing. A frame may include a partially visible boundary bar in addition to the selected span.

The default following view places the latest candle's center at 80% of the plot width, leaving approximately 20% of the plot to its right. Panning toward newer data can move that center as far left as 50% of the plot width. For retained count `count` and viewport span `span`, the default start is `max(0, count - 0.5 - span * 0.8)` and the maximum start is `max(0, count - 0.5 - span * 0.5)`. The minimum start is zero, so short histories can prevent either exact placement. These are plot coordinates, excluding the host's axis margins.

The empty area represents viewport space only: it creates no future timestamps or synthetic candles. Price and volume panes share the same blank area. Hit testing returns `-1` for slots outside retained data; the host hides the candle tooltip while the pointer is there.

The default pane order is price (0), Volume (1), RSI (2), MACD (3), omitting absent studies. All share horizontal bounds with independent vertical scales. Automatic price fitting uses visible highs/lows and enabled price overlays, including BB; Volume starts at zero and fits its visible maximum; RSI stays at 0–100; MACD includes zero and its visible line, signal, and histogram with padding. Price transforms/inversion do not affect auxiliary values. Geometry uses CSS pixels; the browser applies device-pixel ratio and formats labels.

The first effective pan captures both vertical ranges from the viewport **before** moving, even if no frame has been requested yet. Subsequent pans retain those ranges: shared candles move horizontally without changing their height or width. Releasing the pointer, prepending history, and revising or appending live bars keep the ranges locked. A resize changes pixel geometry but preserves the locked price and volume ranges. Invalid pans and pans clamped to the current start do not change scale mode. Public `set_view` and `follow`, effective zoom, and snapshot replacement restore automatic fitting. **Latest** and `End` follow the current dataset or replace a historical snapshot with the current one. Zoom input that cannot change the span at a limit preserves the locked ranges.

`core/layout.zig` defines spacing and the active pane stack. Positive relative weights default to `[0.74, 0.26, 0.26, 0.26]`; inactive weights are retained. Active panes target at least 64 CSS pixels each; when the available plot height is smaller than their combined minimum, they receive equal portions. `resize_pane(upperId, deltaPixels, height)` changes only that pane and its next active neighbor, preserving other panes' weights and heights. Releasing a minimum-height clamp can change the pair's combined weight to preserve those other heights. Positive delta enlarges the upper pane. Legacy `set_pane_split` keeps its 0.30–0.85 price/volume contract. Pane resizing preserves time and locked ranges. All panes are generated and painted in one scheduled frame.

The first effective pan also locks MACD's pre-pan range. Further pan, data updates, history and resize retain it; reset/zoom/follow/configuration refit it together with the other adaptive ranges. RSI remains fixed. Auxiliary coordinates and ticks come from Zig, including unsnapped crosshair conversion. Every pane clips its own drawings; a value outside a locked range never spills into another pane.

Data and indicators continue updating while the scale is locked. Newly visible or updated values may lie outside it until an explicit refit. The renderer clips candles and indicator lines to the price pane and volume bars to the volume pane, so out-of-range geometry cannot spill into the other pane. Scale locking is internal engine state and does not change ABI v1 or any row or metadata layout.

The host samples time labels from actual bar timestamps using stable UTC ordinals for the selected period. Fixed periods use their declared duration, weeks use a Monday origin, and months use calendar-month ordinals rather than a fixed millisecond approximation. It selects a readable slot step from the full viewport span and pixel width, then anchors label selection to those ordinals. Panning therefore moves existing labels with their candles instead of selecting a new label origin from the first visible row; changing right-side blank space or prepending data does not change the selected step. Zoom and width changes can change density. This sampling neither invents future timestamps nor supplies an exchange-session calendar, and missing slots remain unlabeled.

Zoom preserves the pointer's logical position unless the viewport hits a boundary. Prepending history shifts the logical start to preserve the viewed bars, subject to the same bounds. If the latest edge was already visible before an append, the viewport start increases by the appended count, preserving the user's existing right spacing. A view panned to older history stays anchored. Replacing the current candle alone does not move the viewport. **Latest** or `End` restores the default 20% right spacing.

`scale_price(factor, anchor_fraction)` adjusts only the price range around a fraction measured from the price pane's top; factors above one magnify. The core retains time coordinates and the volume range. Linear scaling clamps raw price span to 2–4,000,000,000,000 units and endpoints to ±4,000,000,000,000. Logarithmic scaling operates in log space, bounds raw endpoints to 1e-9–4,000,000,000,000, and retains a two-unit minimum span. At a limit, the minimum span or endpoint bound takes precedence over exact anchoring. Invalid factors/anchors and unchanged spans are no-ops. `reset_scale()` releases vertical locks without changing time or the configured scale transform, and `scale_is_auto()` reports the fitting state. Existing effective horizontal zoom, Latest, replacement, and indicator configuration refits retain their behavior.

`chart/price-scale-controls.ts` owns host events only. It claims the right price axis in capture phase, starts scaling after 4 vertical CSS pixels, and sends incremental factors plus the initial anchor to the core. Upward drag magnifies. Double-click and the Auto/Fixed button reset vertical fitting; Up/Down on the button scales around the price midpoint. Plot gestures, the volume axis, and the time axis remain separate. Button feedback follows core mode, including locks caused by panning.

`chart/time-scale-controls.ts` claims only the bottom axis below `meta[12]` and left of `meta[11]`, excluding the price-axis corner. After 4 horizontal CSS pixels, rightward drag magnifies around the right plot edge using `zoom(factor, 1)`. Wheel input normalizes pixel/line/page deltas and anchors at the pointer's fraction of plot width. Double-click calls `follow()` and restores the default right-side space. Pointer capture, cancellation, and hover belong to the host; no secondary viewport or device-pixel-ratio-dependent coordinates are introduced.

`chart/touch-navigation.ts` observes the first plot contact and claims a pair. It owns contact IDs, capture, gesture thresholds and cancellation; it owns no viewport. Movement events coalesce until the existing paint cycle, with a final flush on normal release. The pair's Euclidean separation controls scale and its horizontal midpoint supplies old/new anchor fractions. A 4-CSS-pixel separation/midpoint change starts navigation; separations below 8 pixels rebase without scaling. Both contacts must start inside the plot, which may span different panes. Axes retain their own gestures.

The additive `transform_view(factor, from, to)` operation computes `newStart = oldStart + from * oldSpan - to * newSpan` with the core's clamped span and fractions. Effective scaling refits ranges; translation with unchanged/clamped span delegates to pan and preserves its range locks. Invalid input has no effect. History and live updates keep their existing viewport rules. Pair takeover cancels drawing previews and single-pointer selection; remaining contacts drain after release/cancel or a third contact so they cannot become accidental clicks/drags. Resize, period changes and explicit cancellation discard pending input. There is no inertia, long-press tracking, separate pane viewport or pinch-specific persistent state.

### Date range navigation

`features/range/` owns UTC calendar bounds, supported-resolution selection, the preset toolbar/date dialog and asynchronous navigation. The calendar entry and `Alt+G` open a draft for one full UTC day or inclusive start/end dates; Apply converts them to `[from, to)`. Cancelling an unsubmitted draft does not load data or change the viewport. Bounds align to the containing candle at the start and clip to the provider's snapshot cutoff at the end. Selection uses candle opening timestamps and retains whole provider OHLC: weekly/monthly candles may include days before the requested start or after the requested end. Presets continue to end at the provider's current snapshot; no computer-clock or exchange-calendar assumptions enter the core.

Custom navigation uses `MarketSession.open(period, before)` to fetch an initial 500-bar snapshot with bar-opening timestamps strictly before the range end, then requests older pages only if needed. The validated exclusive `historyBefore` cursor survives period changes and initial retries; it does not truncate candles or define an as-of replay boundary. Historical browsing invalidates the old subscription, clears pending replay intent and prevents replay from appending a distant current candle onto an incomplete historical sequence. Latest replaces the historical snapshot with the current one and remains paused; its button also recovers from empty/failed historical loads. End and time-axis double-click offer the same return action when chart data is available. The source's `asOf` clock and the requested history cursor are distinct; historical responses without optional `asOf` retain the known current cutoff instead of deriving one from old bars. Late responses cannot cross session generations; range generations prevent obsolete fits after manual navigation. Up to 199 older pages stay within core capacity, and non-progressing pages fail explicitly.

The controller reuses the session and existing shared viewport. `fit_time_range(from, to)` is an additive scalar export: Zig binary-searches loaded timestamps in `[from, to)`, fits their logical range with normal right padding and resets vertical fitting. It returns -1 without changing the view for invalid/empty ranges, 0 for a full fit, or 1 for density clipping. Padding can include other loaded bars; it does not hide data. No additional buffers or allocation are required. The host distinguishes empty ranges, partial available history, density clipping and errors; All accepts the provider's available beginning. Missing sessions remain gaps, without fabricated bars.

### Historical bar replay

The optional `MarketDataSource.replay` capability in `data/replay.ts` owns a separate exclusive cutoff and available end, with `seek`, `reset` and cancellable `advance`. Ordinary history `before` only selects bar-opening timestamps; it cannot truncate OHLC or establish a replay cutoff. All history and aggregation during active replay use the source cutoff, including partial coarse periods. The sample supports deterministic synthetic quarter-minute snapshots, not recovered market ticks. Only fully completed days may enter its aggregate cache.

`MarketSession` owns play/pause, single stepping, speed and cancellation. One step completes the current selected period or adds the next, capped at the available end. Automatic steps wait `1000 / speed` milliseconds after the previous work completes; speeds are 0.25, 0.5, 1, 2, 5 and 10. Period changes reload at the same cutoff; subscriptions, timers and pending steps retire before switching or disposal. `features/replay/controls.ts` presents state only. Start selection uses the shared time mapping in any visible pane and includes the chosen candle through `min(periodEnd, availableEnd)`. Closing the panel pauses and retains that position. Exit resets the source and reloads current data paused; Latest/End/time-axis double-click stay within the active replay snapshot. Providers without the capability expose an unavailable action. Zig continues to calculate indicators and viewport geometry from normalized bars, with no new ABI or second chart model.

While replay is active, the navigation button is labeled **Replay position**. It follows the retained cutoff; returning to current data requires **Exit replay**.

### Price transforms and ticks

`core/price-scale.zig` owns forward/inverse price transforms and tick generation. Modes are 0 regular (`normal`), 1 logarithmic, 2 percentage, and 3 indexed to 100; inversion is independent. `configure_price_scale` preserves the time viewport, volume range, auto/fixed state and any locked raw price range. Automatic ranges are recalculated with the selected mode's padding. Positive automatic log ranges use multiplicative padding `max(log1p(1 / minRawPrice), logSpan * 0.08)`, keeping the lower endpoint positive even for flat or wide data. OHLC, present indicators, drawing projection, pointer conversion, and price readouts use the same core transform. The browser formats labels and displays the requested/effective mode; it does not reconstruct a separate nonlinear scale.

Percentage and indexed modes use the close of the first bar whose center lies inside the viewport, excluding a merely partial bar at its left edge. For base `b`, percentage is `(price - b) / abs(b) * 100`; indexed is `100 + percentage`. Zero or unavailable bases temporarily select the regular effective mode. A negative base remains supported through `abs(b)`. Panning may change the reference and labels while keeping the locked raw range and affine pixel mapping fixed.

Logarithmic mode is a true positive-only transform. Nonpositive visible OHLC, present warmed-up indicators, or raw range endpoints cause a regular effective mode for that frame while preserving the requested preference. A nonpositive drawing anchor alone makes that drawing unprojectable; it does not change the chart mode or autoscale range. Invalid projection returns `NaN` or invalid drawing geometry. Narrow ranges at high prices use `log1p`/`expm1` for numerical stability.

Ticks use readable 1/2/2.5/5/10 steps, with decade-based candidates over wide logarithmic ranges. The core bounds output to 16 ticks, enforces pixel spacing, and exports raw price, projected y, and display value separately. Relative display values are dimensionless; ordinary/logarithmic price labels use the instrument price scale. Raw OHLC and indicator values retain their original units regardless of axis mode.

### Crosshair presentation

`features/crosshair/` resolves interaction against the copied frame and renders through the shared overlay Canvas. Modes are free movement (`normal`, default), snap to close (`magnet`), hidden, and nearest OHLC (`magnetOHLC`). Line/area/baseline use close for both magnets; Volume uses volume; RSI uses its value; MACD selects the nearest available line, signal, or histogram value in its own pane. Unwarmed or clipped values cannot attract the cursor. Hidden mode retains candle readouts. Empty future space has no fabricated bar index or time label.

Crosshair version 1 owns color, width 1–3 CSS pixels, solid/dashed/dotted lines, and separate horizontal/vertical visibility. Its dedicated modal edits a draft; Apply commits and Cancel, close, or Esc discards it. These preferences neither refit axes nor change chart/indicator styles. The host uses core price/pane conversion for unsnapped values and preserves one viewport for all panes.

### Baseline presentation

Baseline is a close-based main series with separate colors above and below its reference, sharing the line width and straight/step path settings. Series preferences migrate valid version 1 fields to version 2. `baselineSource` is `first-visible` (default) or `price`; `baselinePrice` stores integer normalized units in ±1e12. The settings field displays instrument-scaled prices and validates the unit step before applying. Draft cancellation leaves saved preferences unchanged.

First-visible mode uses the core's exported price-axis reference; fixed mode uses the configured raw price. Both request `price_to_y`, including log/relative/inverted modes. The reference does not contribute to automatic range fitting or change the market data. Rendering clips two colored paths and fills to opposite sides of the projected reference; inversion swaps their screen sides, not their raw-price meaning. Gradient opacity rises from 10/255 at the reference to 40% at the pane edge. A reference outside the pane is clipped for filling; a nonpositive reference on a valid log scale stays below all plotted prices. Fills end at the last data point, preserving future whitespace. Selection and crosshair magnets use closing-price geometry; filled regions are selectable within the price pane.

## Workbench, appearance, and drawing documents

The browser workbench gives the chart the available viewport, with a compact toolbar, a drawing rail, and a collapsible watchlist/quote sidebar. Chart settings and drawing objects/styles use separate dialogs. DOM layout stays in the host. Themed DOM dropdowns replace visible native select popups so their options use the same light/dark palette as the page.

Appearance version 3 in `features/appearance/model.ts` owns theme, independent body/border/wick visibility and rising/falling colors, background/grid colors, and grid/last-price visibility. The panel edits a draft: Apply validates, commits, and persists it; Cancel, closing, or `Esc` discards it. Theme changes and reset affect only the draft until applied, preserving indicator settings, data, and viewport. Version 1 and 2 preferences migrate to version 3, initially copying body colors into the new border/wick colors. Version 1's previous dark defaults `#131722` and `#242b3a` become black `#000000` and grid `#202020`. Other custom colors are preserved; old indicator style fields do not belong to chart appearance. The legacy `candleStyle` field is retained only for migration: when `zigchart.series` is absent, its `hollow` value initializes the hollow main-series type. Current main-series type and styles are stored independently in `zigchart.series`.

The settings dialog groups Symbol, Scales, and Canvas while keeping their documents separate. Its reset restores current-theme appearance, default series styling with the chosen series type retained, and default regular/non-inverted scales. Apply commits all three drafts; indicators and crosshair preferences are unaffected. `features/scales/model.ts` validates the version 1 scale preference, which stores requested mode and inversion only, not transient raw ranges or a relative reference.

The top toolbar groups period, main-series type, indicators, replay, and undo/redo controls. Instrument, period, OHLC, and indicator legends are DOM overlays inside the chart container; they share its background without consuming a separate row of layout height. `ui/control-feedback.ts` derives action text, accessible labels, and active/expanded states from the current drawing, panel, and replay state. It does not own or persist business state. A locked drawing offers an unlock action; its hint distinguishes protected geometry/deletion from editable style.

`features/series/model.ts` defines the independent version 2 `zigchart.series` preference: candles, hollow candles, OHLC bars, line, area, or baseline; line color, width 1–4, simple/step interpolation, and top/bottom area colors. Unknown versions and malformed JSON use defaults; supported versions retain valid fields and default invalid fields. Main-series changes preserve data, period, viewport, scales, indicators, and drawing documents. Line, area, and baseline use the existing close values and projected close coordinates; OHLC data remains available to readouts and indicators. Geometry still uses the 17-value frame rows and 13-value metadata of ABI v1.

Automatic price ranges for line, area, and baseline still include the visible OHLC highs/lows and enabled overlay indicators; switching presentation does not refit to closing prices alone. The area gradient uses the configured top/bottom colors with fixed alpha values of 40% at the top of the price pane and 10/255 at its bottom; opacity is not a separate preference.

Main-series selection is transient host state, separate from drawing selection. Clicking the rendered series selects it and shows visible handles; a subsequent handle click opens chart settings. `features/series/selection.ts` consumes the current frame's projected coordinates and renderer-aligned x positions. Line/area/baseline handles use the projected close, while candle/OHLC-bar handles use the open/close midpoint. Hits and markers are clipped to the price pane. Selection does not calculate another price projection or retain frame buffers. A gesture reaching 4 CSS pixels becomes a pan and cannot open settings. Blank clicks or `Esc` clear the series selection; `Enter` on the chart selects first and opens settings on a subsequent press. The instrument title selects without opening settings, preserving access when candle components are hidden.

The right sidebar contains watchlist membership and current-instrument information. `data/catalog.ts` defines four immutable synthetic entries with localized labels and independent scales. The picker and watched rows request selection through the host; membership changes remain separate. `features/watchlist/model.ts` validates its version 1 document against the whole catalog, retaining empty lists. Only the active instrument receives a quote snapshot; inactive rows show unavailable quotes and own no subscription. Quote change uses the latest candle `close - open` in the selected period, with `open` as the percentage base; zero open has no percentage. No daily/session quote is inferred.

Instrument selection validates the catalog entry and binds a fresh `SampleFeed(symbol)` before replacing the stable session source. `MarketSession.replaceSource` retires history, subscriptions, replay timers/steps and queued resume intent, clears the historical cursor, resets replay speed/start state, and loads the selected period paused. Old callbacks remain rejected by generation guards. The host clears quote/frame/gesture state and snapshot cutoff; `RangeController.resetSource()` also clears its cached cutoff and cancels obsolete fits. Metadata getters keep readouts, formatting, baseline inputs, drawing labels and PNG capture on the current instrument. Common appearance, indicator configuration and pane layout remain shared; the core consumes a replacement normalized series with no symbol-specific ABI.

`ui/workspace-layout.ts` composes sidebar input with `pane-resizers.ts`; `layout-preferences.ts` validates version 3 `zigchart.layout`. Version 1's price fraction migrates to price/volume weights with default oscillator weights; version 2 retains its weights. Both receive default order `[0, 1, 2, 3]`. Dynamic separators use copied `Frame.panes`, start after 4 CSS pixels, and combine deltas once per paint. Up/Down changes the adjacent boundary by 8 CSS pixels, Home/End reaches a core limit, and double-click restores only that pair's default ratio while preserving its total weight. Cancellation restores pre-gesture weights; membership changes discard stale boundary input before configuring the core. The sidebar retains a chart column of at least 220 CSS pixels. Width changes use the core spacing clamp; pane changes use shared core geometry.

`ui/pane-actions.ts` owns per-pane controls, consuming copied geometry. The core owns an atomic permutation of price/volume/RSI/MACD IDs and skips absent panes when moving to a neighbor. Weights stay keyed by identity, independent of order. `paneOrder` persists in the layout document; maximization is transient (`-1` restores all active panes) and changes only the visible mask. Removing the focused study clears maximization. Neither reordering nor maximization changes the viewport or locked ranges. Arrangement cancels divider input and restores preview weights before mutation. A hidden price pane exports content bounds `0/0`, no price ticks and invalid price projections; the host hides price legends, drawing input and axis controls. Price header padding and overlays follow its actual bounds after reordering.

Indicator configuration compares active pane masks before and after mutation. A newly enabled Volume, RSI, or MACD pane clears maximization in the core, making every active pane visible while preserving order, weights and the time viewport. Unchanged membership, parameter/style edits and price overlays retain maximization. Parameter/presence changes still refit ranges under the indicator contract. Removing the focused study restores the remaining panes; removing another study retains focus.

The analysis library groups Indicators, Strategies, and Scripts, with trend, volume, oscillator and volatility indicator groups. Version 4 `zigchart.indicators` migrates version 1/2/3 settings, preserving extra averages and supplying disabled BB defaults. Version 1/2 receive an empty `averages` list; version 1 also receives disabled RSI/MACD defaults. All studies start absent. The original MA/EMA and up to six extra MA/EMA instances own period/color/width; extra IDs `average-1` through `average-6` map to fixed numeric slots independently of list order. Add another copies the original study's settings; deleting an extra frees its slot without renumbering others. Built-in study removal retains settings. Volume owns colors/opacity; RSI owns period/color/width and reference levels (`0 <= lower < upper <= 100`); MACD owns three periods, line/signal/histogram colors and width. BB owns period/multiplier, independent basis/upper/lower/fill colors, width 1–4, a fill switch and opacity 0–1. Invalid fields or duplicate/unknown extra IDs reject the whole document. Removed studies release their legends/panes; style-only changes preserve ranges. Strategies and Scripts remain explicit unavailable states.

Horizontal/vertical lines, horizontal rays, trend segments, rays, extended lines, rectangles, Fibonacci retracements and text annotations are host-owned objects with stable IDs and UTC-time/integer-price anchors. `core/drawings.zig` projects batches, converts pointer locations, translates anchors by retained bar slots, and tests edges/handles using the same frame transform as candles. It clips line extensions parametrically to the price pane and reuses that calculation for hit testing. Original projected anchors remain separate from the clipped stroke so handles do not move to pane edges. Object styles, selection, locks, input gestures, document validation, persistence, and edit history belong to TypeScript. `features/drawings/tools.ts` groups single/two-point tools; `panel.ts` presents object/style controls in a separate dialog. The core does not own an editor document or call browser APIs.

Anchors snap horizontally to existing retained bars and vertically to integer price units. Future blank space and the volume pane cannot receive anchors. Missing historical anchors produce invalid geometry until the relevant bars are loaded. A horizontal line extends across the price pane; a trend is a bounded segment; a rectangle is selected on its edges or two opposing control points, not its filled interior. Drawings are clipped to the price pane and do not expand its automatic range. Slot-based translation follows actual retained timestamps across data gaps.

Vertical lines span only the price pane. Horizontal rays extend rightward from A; rays continue from A through B (including leftward), while extended lines continue both ways. Straight lines are defined after the shared price transform, including logarithmic/inverted modes. Coincident anchors produce a point until edited, not an arbitrary direction. A visible extension remains selectable when both anchors are outside the viewport. Line extensions support future-space selection, but their drag pointer must resolve to an existing bar. Single-anchor edits synchronize A/B. The version 1 document shape is unchanged and accepts the added kinds; older builds that do not know a kind reject that document.

One completed drag or style change creates one edit; previews do not fill undo history and `Esc` cancels them. Live bar updates are not document edits. Locked objects remain selectable and accept style changes, but cannot be dragged or deleted until unlocked. Each period is isolated and limited to 256 objects and 100 undo steps. A restored document starts with empty undo/redo history and no selection; changing periods replaces the series and projects only that period's objects.

Optional `localStorage` keys include `zigchart.locale`, `zigchart.period`, `zigchart.appearance`, `zigchart.series`, `zigchart.scales`, `zigchart.crosshair`, `zigchart.indicators`, `zigchart.layout`, `zigchart.watchlist` and catalog-validated `zigchart.symbol`. `features/instruments/model.ts` keys drawings by `zigchart.drawings:${encodeURIComponent(symbol)}:${priceScale}` and fixed baseline source/price by `zigchart.baseline:${encodeURIComponent(symbol)}:${priceScale}`. Each drawing document retains its per-period edits in memory, including when storage fails. Drawing version 1 validates symbol, scale, periods, IDs, anchors/styles and object limits; baseline version 1 validates source and integer price. Only original ZIG/USD may fall back to legacy `zigchart.drawings` and global baseline fields; legacy records are not deleted. Global series writes reset baseline fields to defaults so raw price units cannot leak between symbols. Unknown or malformed preferences fall back safely. These records contain settings and drawings, not market data or a saved replay clock.

Indicator widths are integer CSS pixels from 1 to 4, colors are six-digit hexadecimal values, and volume opacity is 0.1–1. Storage access failures leave the current session usable.

Fibonacci objects use `core/fibonacci.zig` for prices, shared-axis projection and horizontal clipping; hit testing consumes the same levels. Default interpolation is `B + ratio * (A - B)`, with reverse exchanging A/B. Optional log interpolation applies only on an effective logarithmic axis and positive anchors, using `log1p`/`expm1` for narrow high-price ranges. Ratios are finite within −10..10; derived prices retain f64 fractions and labels use instrument precision. Offscreen finite levels remain available for clipped band fills. Nonfinite projections are omitted; drawings never affect auto-fit.

The host's `chart/fibonacci.ts` encodes numerical options; independent `features/drawings/fibonacci-model.ts`, `fibonacci-controls.ts` and `fibonacci-render.ts` own styles, editing and Canvas presentation. Each object stores 1–24 levels with enabled flags/colors, line style, labels and opacity. Numeric edits commit on change, blur or Enter without replacing the focused field; invalid drafts do not change the document. Version 1 drawing documents accept a `fibonacci` payload only for that kind. The parser's 16-million-character bound accommodates styled levels across supported periods; browser storage quota may be smaller, with existing unsaved-state feedback on failure. Templates remain a future extension.

Text kind 8 has one data anchor at the box top-left; edits synchronize A/B. The host modules `text-model.ts`, `text-controls.ts` and `text-render.ts` own plain content, controls and system-font wrapping. Version 1 drawing documents require a `text` payload only for this kind: nonblank LF-normalized content up to 1,000 UTF-16 code units and 20 explicit lines, integer font size 10–48 and wrap width 80–640 CSS pixels, bold/italic, background/border flags and colors, and background opacity 0–1. Text inherits object color; the border inherits object width. Automatic wrapping may create additional visual lines. Field changes commit on blur/change or Ctrl+Enter for content, preserve input focus, and use existing document undo/persistence; locking still permits content/style edits.

Font metrics stay in the browser. The same bounded cached layout supplies Canvas/PNG text rendering and a two-f64 width/height batch for Zig hit testing. Core projection uses the existing shared price transform and loaded anchor; hit testing clips the whole box to the price pane and retains topmost-object precedence. No text, font APIs or document state enter Zig. Missing historical anchors wait for loading, future-space anchors remain invalid, and text never expands auto-fit. Screen-fixed text, rich text and inline chart editing are outside this implementation.

A text body can start dragging anywhere inside its visible box, including over right-side blank space. `drawing_shift` converts pointer displacement in Zig: horizontal movement rounds to retained-bar slots using the current shared spacing (halfway values away from zero); vertical movement applies the inverse shared price transform at the original anchor Y plus pointer delta. Both pointer positions must lie inside the price pane, and original/final anchors must resolve to loaded timestamps. Final prices are integer units within ±1e12 and positive on an effective logarithmic axis. The operation preserves viewport/ranges and synchronizes text A/B; no future timestamps are fabricated.

Temporary measurements keep UTC/integer-price anchors in `features/measure/`; `core/measurement.zig` owns statistics and shared-axis projection. Both anchors must resolve to loaded bars and valid price-pane coordinates. Price change is `B - A`; percent is `(B - A) / abs(A) * 100`, unavailable at zero A. Signed bar distance is `indexB - indexA`, while inclusive count is `abs(distance) + 1`; elapsed time is the actual signed UTC difference, preserving gaps. Volume includes both endpoints, sums in `u64`, and becomes unavailable above `2^53 - 1`; an unfinished bar contributes its current cumulative volume. The scan is proportional to the selected retained span, with no allocation or indicator recalculation. Projection respects reordered price panes, logarithmic scales and inversion; it does not change auto-fit.

The ruler accepts two clicks or a drag of at least 4 CSS pixels, with Shift as a shortcut. Completion disarms input and retains data anchors for repainting. Esc, the next chart click, tool/navigation changes, session reset and replay selection clear it. Resizing cancels unfinished input but reprojects a completed result; pinch takes priority over a pending measurement. This transient overlay is separate from drawing documents, undo and PNG export. The bridge immediately copies the additive ten-value result; existing ABI v1 rows remain unchanged.

## Chart images and fullscreen

Chart-image export is host-owned in `features/export/`. Before capture, the workspace cancels transient gestures and paints a current full frame; it projects committed drawing objects through the existing core interface. `scene.ts` reuses `drawChart` and annotation rendering with copied geometry, and adds localized instrument/period, the latest loaded bar's OHLC, UTC/sample labels and visible indicator legends. Visible pane order and maximization are preserved. Crosshair, selection, unfinished edits and workbench controls are excluded. The export uses a fresh Canvas sized from the logical chart area plus a 56 CSS-pixel header and 26 CSS-pixel footer, never the live Canvas's reusable capacity. Effective pixel ratio is bounded by 8,192 pixels per side and 16,000,000 total pixels; output may be downsampled. Rasterization finishes synchronously before asynchronous PNG encoding, freezing one state. Filenames sanitize symbol/period components. Preview URLs are revoked on close/retry/disposal, and generation checks discard stale encoding results. This introduces no data, viewport or Wasm ABI contract.

`ui/fullscreen.ts` uses the browser Fullscreen API on `document.documentElement`, so body-mounted dialogs remain part of the fullscreen workspace. Applied state comes from `fullscreenElement`/`fullscreenchange`, not an optimistic toggle. The control reports busy, unavailable, rejected and other-element-fullscreen states; disposal releases its listeners. Fullscreen geometry changes go through the existing resize scheduler.

## Host localization

English and Simplified Chinese presentation belongs entirely to the browser host. One locale selection controls DOM text, Canvas labels, tooltips, loading/status/error messages, accessibility labels, document language, title, and description. Locale-specific number and date formatting changes presentation only: timestamps stay in UTC, numeric values retain their original units and precision, and the Zig engine and Wasm ABI remain language independent.

On startup, use a valid saved preference first. Otherwise choose the first supported language from the browser's preference list, falling back to English when none matches. The host stores an explicit language choice under `zigchart.locale` in `localStorage`. Reading or writing storage may fail without preventing startup or an immediate language switch; persistence is then unavailable.

A language switch updates presentation without reloading the page or replacing the core instance. Loaded data, viewport, locked vertical ranges, replay progress and subscription, indicator visibility, and pending history requests remain intact. Dynamic states must render using the current language, including when an outstanding request completes after a switch. User-facing errors provide localized context, while the console retains the original diagnostic for debugging. Maintain both message dictionaries together; identifiers and code comments remain English.

`chart/format.ts` provides shared locale-aware formatting for axes, readouts, and quotes using instrument scales. Scales must be positive safe integers whose reciprocal terminates within 20 decimal places (only factors 2 and 5); standard integer-value formatting preserves those decimal units exactly. Fractional indicator and axis values round to the display precision; compact volume labels intentionally abbreviate. Invalid scales throw instead of silently rounding a nonzero unit to zero.

Manual scale state remains transient in the core and is not restored after reloading the page.

## Memory and lifecycle

The Wasm module uses fixed arrays for retained bars, indicators, batch input, frame/axis/tick output, inspection output, and drawing input/output. Calls do not allocate or grow linear memory. This trades a predictable fixed allocation for a strict capacity limit. There is no automatic eviction or streaming archive; reaching capacity is an error that the host must handle.

Pointers expose borrowed, reusable buffers. The bridge writes a complete input batch before calling `apply`; it copies frame arrays and returns ordinary inspection objects before exposing results. Callers must not retain raw views across core calls, even while this implementation keeps memory fixed. Any future growable-memory design must recreate views after growth and preserve this ownership contract.

After generating a valid frame, the Wasm boundary caches that frame's price transform and pane geometry. Same-size read-only coordinate conversions reuse them without rescanning visible bars. Every data, viewport, scale, indicator or layout mutation invalidates the cache; different dimensions use a fresh calculation. This cache owns numeric core state only, not host views or market snapshots. It does not skip frame generation or indicator updates.

Each chart gets a separate WebAssembly instance; there are no shared global chart handles across instances. Releasing host references makes its memory eligible for garbage collection. Browser cleanup must also cancel pending history, unsubscribe the feed, and disconnect observers. The host schedules at most one pending paint with `requestAnimationFrame`. Resize observations request a paint; backing-store dimensions, CSS geometry, the core width constraint, and redraw are committed together in that paint, avoiding an intermediate cleared Canvas frame.

The base Canvas draws the chart and drawing objects; a transparent overlay draws the crosshair and main-series selection. One scheduler merges full-chart and overlay-only invalidations, with a full redraw taking precedence. Pointer-only motion can reuse the copied frame and redraw only the overlay; data, viewport, appearance, series, indicators, drawing edits, and layout changes request a full redraw. Both surfaces use identical committed dimensions, device-pixel ratio, and transforms. The overlay does not create another viewport or retain borrowed Wasm views. Separating these layers does not by itself establish a performance improvement; browser measurements must include the actual workload.

`chart/surface.ts` separates Canvas capacity from visible viewport dimensions. Capacity grows in 128-CSS-pixel increments and is reused when the viewport shrinks; the container clips the excess surface. Every width change still updates core geometry and redraws for the current logical viewport, without stretching an old image. Resize observations matching the committed dimensions do not schedule another paint. OHLC and related text update only when their displayed values change.

The chart container uses `overflow: clip`, not a scroll container: focus and DOM updates must not programmatically scroll the logical viewport into unused Canvas capacity. Surplus pixels stay clipped after resize, theme and fullscreen changes.

## Extension boundaries and limits

The feed interface is the integration boundary for purchased data. Credentials belong in a future provider backend or another appropriate secure host, not the shipped browser bundle. The MVP sample requires no external service.

The current bound is four named panes, six built-in studies and six extra MA/EMA instances. Arbitrary panes, multiple oscillator/BB instances and public plugins require an explicit extension to the numeric contract, without reinterpreting existing columns. Main-series choices change rendering only. Python 3 scripts and strategies belong in separate execution hosts with explicit inputs and outputs; there is no interpreter, execution sandbox, order model, or backtest engine in this MVP. Four synthetic instruments can be selected one at a time. Network reconnects, session calendars, adjusted history, tick aggregation, concurrent multi-instrument charts, and market-data persistence remain outside the implemented chart scope.
