# Charting references

[English](references.md) | [简体中文](references.zh-CN.md)

Checked on 2026-09-20 using the official repositories and documentation below. Repository links refer to the inspected default branches and can change. This is a source and documentation review, not a comparative runtime benchmark or a claim of feature parity.

## Open-source implementations

| Reference | Observed design | Decision for ZigChart |
| --- | --- | --- |
| [KLineChart](https://github.com/klinecharts/KLineChart) | Canvas chart implementation with separate chart, store, pane, event, and indicator components. | Learn from shared pane layout and explicit coordinate conversion; keep our data and geometry in the platform-independent Zig core. |
| [KLineChart Pro](https://github.com/klinecharts/pro) | Application shell on top of KLineChart, with a provider interface for symbol search, historical bars, subscriptions, and teardown. | Keep provider integration outside the chart core; implement only the provider operations needed by the MVP. |
| [Lightweight Charts](https://github.com/tradingview/lightweight-charts) | Separate series and time-scale APIs, full data replacement, latest-bar updates, and logical-range queries for historical loading. | Specify update ordering and viewport anchoring explicitly; use one horizontal coordinate system across all enabled panes. |

The reviewed implementation and API entry points are:

- KLineChart [Chart.ts](https://github.com/klinecharts/KLineChart/blob/main/src/Chart.ts) and [DataLoader.ts](https://github.com/klinecharts/KLineChart/blob/main/src/common/DataLoader.ts). The chart computes shared pane widths; its data loader separates historical batches and live subscriptions.
- KLineChart Pro [types.ts](https://github.com/klinecharts/pro/blob/main/src/types.ts) ([source](https://raw.githubusercontent.com/klinecharts/pro/main/src/types.ts)). Its history, subscription, and unsubscribe operations carry symbol and period metadata. ZigChart follows this explicit period/lifetime separation with its own typed interface, cancellation, and request-generation checks.
- KLineChart's [overlay guide](https://klinecharts.com/en-US/guide/overlay) describes drawing lifecycle, data-coordinate points, control handles, selection, drag events, locks, and style overrides. ZigChart uses these interaction concepts for its independently implemented drawing editor, keeping projection and hit testing in Zig and document edits in the host. It does not implement KLineChart's overlay API or full tool set.
- Lightweight Charts [series API](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/ISeriesApi) and [data-layer.ts](https://github.com/tradingview/lightweight-charts/blob/master/src/model/data-layer.ts). `setData` replaces ordered data; `update` normally replaces the latest timestamp or appends a newer one. Historical updates are an explicit separate option. Logical range queries support requesting history near the left edge.

These are engineering references only. No implementation, styles, images, or chart package from these projects is included in the MVP. The implementation decisions above are our conclusions from the review, not guarantees provided by the reference projects. See [THIRD_PARTY.md](../THIRD_PARTY.md) for license boundaries.

The official Lightweight Charts 5.2 [price-mode](https://tradingview.github.io/lightweight-charts/docs/api/enumerations/PriceScaleMode), [crosshair-mode](https://tradingview.github.io/lightweight-charts/docs/api/enumerations/CrosshairMode), [series](https://tradingview.github.io/lightweight-charts/docs/series-types), and [plugin](https://tradingview.github.io/lightweight-charts/docs/plugins/intro) documentation was also checked on 2026-09-21. The [feature map](feature-map.md) uses these categories to separate implemented behavior from partial and pending capabilities. ZigChart defines its own reference, fallback, numeric-range and persistence contracts; matching mode names do not establish identical edge-case behavior or API compatibility.

Lightweight Charts documents [resizable panes](https://tradingview.github.io/lightweight-charts/docs/panes) and a [minimum bar spacing in pixels](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/TimeScaleOptions#minbarspacing). These inform ZigChart's adjacent-pane dividers and width-aware zoom bound. ZigChart chooses 6 CSS pixels between candle centers as its readability limit; the upstream `minBarSpacing` default is 0.5 pixels, not 6. Pane geometry remains in Zig, and the host paints up to four built-in panes from one shared frame and time viewport.

The official [series API](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/ISeriesApi#update) distinguishes ordinary latest-bar updates from explicitly requested historical updates. ZigChart independently adds a batched `correct` operation for existing timestamps, with atomic validation and suffix indicator recomputation. The official [series types](https://tradingview.github.io/lightweight-charts/docs/series-types) also include baseline charts. ZigChart supports fixed-price and first-visible-close references through its own Zig price projection and Canvas renderer. These are behavioral references, not imported source or an API-compatibility claim.

The official [range-switcher example](https://tradingview.github.io/lightweight-charts/tutorials/demos/range-switcher) and [time-scale API](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/ITimeScaleApi#setvisiblerange) were reviewed on 2026-09-21. ZigChart independently separates date-range presets from candle resolution: the host loads a suitable real resolution and Zig fits timestamps in the shared viewport. No example source is included.

Crosshair behavior was checked against [Lightweight Charts v5.2.0 magnet.ts](https://github.com/tradingview/lightweight-charts/blob/v5.2.0/src/model/magnet.ts) on 2026-09-21. Normal mode leaves the pointer price unchanged; Magnet considers close, while MagnetOHLC considers open, high, low and close. Candle direction does not choose a different field. ZigChart independently implements these options and defaults to free movement for price inspection.

The official [chart screenshot API](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/IChartApi#takescreenshot) and pinned [v5.2.0 chart-widget.ts](https://github.com/tradingview/lightweight-charts/blob/v5.2.0/src/gui/chart-widget.ts) were reviewed on 2026-09-21. The API returns a Canvas and excludes crosshair by default. That source commits pending drawing invalidation, then composes pane, separator and axis bitmaps into a separate Canvas. ZigChart independently renders its copied frame and committed drawings into a bounded image, adds localized chart metadata, and excludes editing feedback. This is a behavioral reference; no screenshot implementation or API was imported.

## Indicator formulas

TradingView's official [RSI](https://www.tradingview.com/support/solutions/43000502338-relative-strength-index-rsi/) and [MACD](https://www.tradingview.com/support/solutions/43000502344-moving-average-convergence-divergence-macd-indicator/) explanations were checked on 2026-09-21. They provide formula references: RSI compares smoothed gains and losses; MACD subtracts the slow moving average from the fast one, with a signal average and a histogram equal to MACD minus signal. ZigChart implements these calculations independently and chooses EMA for both MACD averages and its signal.

ZigChart's initialization contract is explicit: RSI defaults to 14 close-to-close changes, seeds average gains and losses from the first full period, then applies Wilder smoothing; a flat seed yields 50. MACD defaults to 12/26/9 and uses a full-period SMA seed for each EMA, including the signal EMA's first available MACD values. Its histogram has no factor of two. Unavailable warm-up values remain NaN. RSI uses a fixed 0–100 pane; MACD's automatic range includes zero. These local seed, flat-market and range choices do not establish identical values or revision behavior to TradingView.

TradingView's official [Bollinger Bands explanation](https://www.tradingview.com/support/solutions/43000501840-bollinger-bands-bb/), checked on 2026-09-21, documents a moving-average basis with standard-deviation bands and defaults of close, length 20 and multiplier 2. ZigChart independently specifies a close SMA, population variance divided by `N`, and NaN until a full window exists. The source page does not specify that divisor; it is an explicit local contract. Only one BB instance is supported, without alternate sources/basis types, offsets or separate calculation timeframes. No source code was imported and exact platform parity is not claimed.

## Product references

The official Advanced Charts [required datafeed methods](https://www.tradingview.com/charting-library-docs/latest/connecting_data/datafeed-api/required-methods/), reviewed on 2026-09-21, separate symbol search, metadata resolution, history and subscriptions. ZigChart independently uses a finite synthetic catalog, instrument-bound source instances and cancellable session replacement. Metadata remains in the host, and selecting a watchlist member is separate from managing membership. This is a design reference; the Advanced Charts API and implementation are not imported or reproduced.

TradingView's official [Text drawing tool guide](https://www.tradingview.com/support/solutions/43000516983-text-drawing-tool/), reviewed on 2026-09-21, describes chart-point text that moves with scrolling, font styling, wrapping, backgrounds and borders. ZigChart independently implements these common behaviors with a single data anchor, bounded plain text, a dedicated editing dialog and browser-measured numeric hit boxes consumed by Zig. Screen-fixed text, inline editing and general timeframe-visibility rules are not implemented; no source code or assets were imported and exact platform parity is not claimed.

TradingView's [date and price range tools](https://www.tradingview.com/support/solutions/43000516996-date-and-price-range-drawing-tools/) and [Shift measurement shortcut](https://in.tradingview.com/support/solutions/43000537228-how-to-use-measure-tool-quickly/), reviewed on 2026-09-21, describe measuring between two chart points with price/time statistics and a keyboard shortcut. ZigChart independently implements a temporary ruler, specifying signed distance, inclusive bar count/volume, actual UTC differences and precision limits in its own core. These endpoint rules are local contracts, not exact platform parity; persistent range drawings, tick/pip inference and the full style editor are not included. No source or assets were imported.

TradingView's official [Bar Replay guide](https://www.tradingview.com/support/solutions/43000474024-how-do-i-turn-bar-replay-on/), reviewed on 2026-09-21, describes selecting a starting candle, play/pause, adjustable speed, stepping, reselection and returning to current data. These guide ZigChart's independently implemented replay toolbar. Its optional provider capability, exclusive cutoff, synthetic partial-minute rules and period stepping are local contracts; multi-chart replay and trading simulation are not implemented. No product code or assets were imported.

TradingView's [ray](https://www.tradingview.com/support/solutions/43000518113-ray-drawing-tool/), [extended line](https://www.tradingview.com/support/solutions/43000518131-extended-line-drawing-tool/), [horizontal ray](https://www.tradingview.com/support/solutions/43000518121-horizontal-ray-drawing-tool/), and [vertical line](https://www.tradingview.com/support/solutions/43000518093-vertical-line-drawing-tool/) pages identify drawing categories and editing conventions. ZigChart implements their basic geometry independently in Zig with host-owned documents and gestures. Arrowheads, labels, pane-wide vertical synchronization, and full upstream style/visibility options are not implemented.

Lightweight Charts exposes price/time-axis dragging, wheel scaling and double-click reset in [HandleScaleOptions](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/HandleScaleOptions), and automatic fitting through [PriceScaleOptions](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/PriceScaleOptions). These document conventions used by ZigChart's independent axis controllers. ZigChart chooses right-edge anchoring for time-axis drag and follow-latest on time-axis double-click; these are explicit local contracts. Zig computes shared transforms, inverse coordinates and readable ticks, while the browser handles input and formatting. No upstream implementation was copied and API compatibility is not implied.

The [Lightweight Charts chart widget](https://github.com/tradingview/lightweight-charts/blob/master/src/gui/chart-widget.ts) avoids unchanged-size work and merges invalidations into scheduled drawing. ZigChart independently batches divider input and commits Canvas dimensions immediately before painting. Its pane lifecycle and per-series settings also inform optional, separately configured studies; this does not imply API compatibility or comparable performance.

[fuchenru/TradingHero](https://github.com/fuchenru/TradingHero) describes a stock-analysis application that integrates TradingView visualizations. It is not established as the source of tradinghero.com and is not used as the chart implementation here. Product screenshots inform control grouping and visual hierarchy, without importing branded assets or proprietary styles.

[MetaTrader 5 chart documentation](https://www.metatrader5.com/en/trading-platform/charts) and [technical analysis documentation](https://www.metatrader5.com/en/trading-platform/technical-analysis) show useful product conventions: readable OHLC information, indicators on the price chart or separate scales, manual scaling, and reusable chart settings. These inform usability work. Trading, scripting, complete saved workspaces, and strategy testing remain outside this MVP; local appearance preferences and drawing documents are implemented separately. The product pages do not establish a right to redistribute the platform, artwork, or source code.

[TradingView](https://www.tradingview.com/) is a product reference, distinct from its open-source Lightweight Charts library. Its [official product comparison](https://www.tradingview.com/charting-library-docs/latest/product-comparison/) distinguishes hosted widgets, Lightweight Charts, and Advanced Charts. Neither chart library includes market data. Widgets use TradingView-hosted data and do not accept an arbitrary replacement feed.

The [Advanced Charts datafeed documentation](https://www.tradingview.com/charting-library-docs/latest/connecting_data/Datafeed-API/) is useful for identifying integration edge cases: ordered historical bars, explicit end-of-history, indicator warm-up history, complete replacement of the current bar, and independent subscription lifetimes. ZigChart defines its own protocol; it does not promise API compatibility.

The [resolution documentation](https://www.tradingview.com/charting-library-docs/latest/core_concepts/Resolution/) distinguishes minute/hour resolutions from calendar units and ties available choices to datafeed capabilities. ZigChart's supported-period catalog exposes only periods its synthetic provider can deliver. Its UTC aggregation, Monday weeks, calendar months, and unavailable seconds are explicit sample rules, independently implemented and not a claim of TradingView resampling compatibility. Screenshots and product interfaces inform workbench density and control placement; no proprietary assets, code, or styles are copied.

Advanced Charts has separate usage terms: its [introduction](https://www.tradingview.com/charting-library-docs/latest/introduction/) describes free use with visible attribution in public environments, excluding private or paywalled use. Do not assume the Lightweight Charts license covers Advanced Charts, TradingView's website, or its market data.

TradingView's [Fibonacci retracement guide](https://www.tradingview.com/support/solutions/43000518158-fibonacci-retracement-drawing-tool/) documents two-point retracements, configurable levels, extensions, reversal and optional logarithmic calculation. It is a product-behavior reference, not part of Lightweight Charts. ZigChart independently defines and implements its numerical rules, limits and object controls in `core/fibonacci.zig` and `features/drawings/fibonacci-*`; no implementation or artwork is imported.

The official [HandleScaleOptions](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/HandleScaleOptions) and [HandleScrollOptions](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/HandleScrollOptions) document pinch scaling and touch dragging as distinct controls. ZigChart's independent touch controller preserves the shared Zig viewport, defines explicit takeover/release rules and coalesces pointer movement. Device validation, inertia and long-press tracking remain separate work.

## Evaluation order

First establish deterministic behavior for historical prepend, current-bar replacement, indicator initialization, invalid input, and main/subchart alignment. Then measure the same workloads across candidate implementations before making performance comparisons. Record browser version, hardware, viewport, device-pixel ratio, retained/visible bar counts, update rate, and measurement method. A faster core calculation alone does not demonstrate lower input-to-display latency or better end-to-end chart performance.

The initial Zig + WebAssembly + TypeScript + Canvas 2D implementation keeps the browser renderer replaceable without requiring a future renderer migration. No competitor superiority claim is made by this MVP.
