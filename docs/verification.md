# Verification

[English](verification.md) | [简体中文](verification.zh-CN.md)

This document defines reproducible checks. It is not a record of completed runs. Report actual commands, environment, results, and unverified scope with each change; do not infer browser correctness from compilation or unit tests.

## Automated checks

Date ranges: cover leap-day/month-end clamping, supported-resolution selection, exclusive end bounds, sparse timestamps, density clipping, non-progressing history and cancellation/retry. In the browser, select one month, All, then one day; verify the actual period changes, All reaches the provider's oldest history, the snapshot cutoff does not jump to month end, all panes remain aligned and manual pan clears the selected preset. Check both interface languages and logs.

Crosshair regression: within the same rising or falling candle, default/free mode must follow several pointer heights while retaining the bar's OHLC readout. Explicit close magnet must use close in either direction. Check the applied mode in the settings trigger tooltip, Apply/Cancel, reload persistence and both languages; do not overwrite valid saved modes when changing defaults.

For multiple averages, compare distinct MA/EMA periods against independent formulas through warm-up, revisions, corrections and prepends. Verify atomic invalid-batch rejection, inactive slots, copied outputs, auto bounds/log fallback and unchanged locks on identical configuration. In the browser, add another average, edit it independently, remove the original, reload and switch language; its identity/settings must survive. Check the six-extra limit and remove only the test instances. The benchmark includes a separate 100,000-bar, eight-average workload for tail updates and frame copying; it excludes browser rendering.

From a clean checkout with the pinned Node/npm versions:

```text
npm ci
npm run setup:zig
npm run check:architecture
npm run check:docs
npm test
npm run build
```

`npm test` runs native Zig tests, builds the Wasm module, and runs host tests against that real module. `npm run build` rebuilds Wasm, checks TypeScript, and produces the Vite production bundle. Native engine tests and Node-hosted Wasm tests cover different boundaries; neither executes Canvas or browser events.

`npm run check:architecture` parses TypeScript module references to reject data dependencies outside `data/`, reusable-module dependencies on `app/` (except the `main.ts` bootstrap), and explicit relative runtime cycles. Fixture tests include accepted type-only cycles and rejected ownership/runtime edges, with CLI success/failure exit codes. Computed dynamic imports and future aliases need separate review; the guard does not replace TypeScript or browser validation.

`npm run check:docs` checks the eight English/Chinese document pairs, reciprocal language links, LF line endings, and local link targets. When `DOCS_BASE_REF` is set to a commit SHA, it also checks that documentation changes between that commit and `HEAD` include both language versions. CI supplies that comparison reference when available. This checks structure and paired changes, not translation accuracy or semantic equivalence; maintainers must review both versions together.

Maintain coverage for invalid/duplicate/out-of-order data, atomic rejection, current-bar replacement, append/prepend, MA/EMA seed and warm-up, full-snapshot equivalence, viewport anchors, zero volume, flat/negative prices, copied outputs, and independent module instances. Feed tests should cover deterministic data, the exclusive history cursor, replay revisions, cancellation, and invalid requests.

For RSI/MACD, use small numerical fixtures to verify Wilder's first full-period gain/loss seed and flat RSI of 50, full-SMA EMA seeds including MACD's signal, warm-up NaNs, and `histogram = MACD - signal`. Compare repeated final-bar revisions and append/prepend results with full recomputation. Verify price/Volume/RSI/MACD share one horizontal viewport and aligned rows, including missing warm-up values, removal/re-addition, and adjacent resizing. Confirm data, indicator configuration and pane layout changes invalidate cached frames; pointer-only reuse must not expose stale geometry or values.

Period checks should compare aggregated OHLCV against the same canonical minute fixture, including cumulative current-minute replacement, hour/day boundaries, Monday weeks, February in leap and non-leap years, and transitions between unequal calendar months. Verify exclusive cursors and partial-last-bar metadata at every resolution, the 49 initial monthly bars, rejection of unsupported seconds, and replay-clock continuity across period switches. Simulate rapid switches with an adapter that ignores cancellation: stale history, stream values, and errors must not change the new session.

Drawing checks should cover time-anchor projection across prepend, pan, zoom, resize, and timestamp gaps; integer-price conversion; pane and future-space rejection; topmost edge/handle selection; and copied Wasm outputs. Host checks should cover one undo step per committed edit, canceled previews, undo/redo branches and limits, locked geometry/deletion, period isolation, document restoration, wrong symbol/scale/version, duplicate IDs, malformed coordinates, and the 256-object limit. Preference checks should cover JSON round trips, invalid indicator settings, appearance migration, independent defaults, and unavailable storage.

Host localization checks should cover matching message keys and interpolation parameters in both languages, valid saved-language precedence, browser-language selection and English fallback, unavailable preference storage, and UTC-preserving number/date formatting. These checks supplement actual browser verification of translated DOM and Canvas content.

Native and Wasm regression checks should cover default right spacing, panning the latest candle to the plot center, preserving a chosen right gap during append, restoring default spacing with follow, and keeping older views and historical prepend anchors stable. Check short-history bounds, rejection of hits in empty future slots, unchanged stored bars, and shared horizontal placement across all added panes.

For pan scale regressions, compare the same retained candle before and after movement: X must translate by the expected amount while candle width, price/volume ranges, and unchanged values' Y coordinates remain fixed. Include panning before the first frame, releasing and repeating a pan, resize mapping, history prepends that recalculate EMA, and live revisions/appends in both following and older views. Verify that invalid or clamped no-op pans keep the previous mode, and that explicit view/zoom/follow and replacement restore automatic fitting, including after an empty snapshot. Host tests should verify that UTC tick timestamps remain stable during fractional pans and arbitrary history prepends, use density derived from the full viewport despite right-side blank space, and change density with zoom or width. Missing intervals must not create synthetic labels. Pane clipping also needs actual browser verification.

Price-axis checks should cover the initial top-relative anchor, unchanged time and volume, finite span/endpoints, invalid inputs, no-op limits, and reset without horizontal movement. In the browser, verify upward/downward drag after 4 vertical CSS pixels, click-only input, ignored volume/time axes, cancellation, double-click reset, Auto/Fixed feedback after panning, and the button's Up/Down keys in both languages. Manual scales must survive resize and market updates but are not saved across reloads. Compare mature EMA revisions against a full recomputation for short and long periods; check scale-8/32/1e9 formatting and rejected scales, plus throwing subscription cleanup during Pause, period switches, and disposal.

The CI workflow runs installation, compiler setup, architecture and documentation checks, tests, and a production build on Windows and Linux. It contains no deployment or release step. A local run does not establish that the remote workflow passed. macOS and arm64 compiler download entries do not establish tested execution on those platforms.

Correction tests compare sparse historical batches against a full rebuild across all indicator seeds and mature recursive state. Reject missing targets, duplicates, malformed rows and ordinary historical upserts without partial mutation. Check correction after prepend, cache invalidation, fixed ranges, drawing anchors and subscription cancellation/error paths. Provider ordering and real-feed correction races require integration tests with that provider.

## Browser checklist

Start `npm run dev`, or `npm run preview` after a production build. Use the browser's actual interaction mechanisms and record the browser version, viewport, and device-pixel ratio.

1. Confirm `core.wasm` loads successfully, select the one-minute period, and verify 500 sample candles load and replay starts paused. Without saved indicator preferences, only candles should appear, with no indicator legends or empty volume pane. Add the indicators needed for the following checks through the library. Check the synthetic-data label and visible error state. The latest candle's center should start at 80% of plot width; added panes share the same right gap. Other periods may load fewer bars when the fixture has less history.
2. Move across all added panes: the crosshair, selected UTC time, OHLC, volume, and indicator values must refer to the same bar. Confirm candle, volume and oscillator points align horizontally; warm-up values must remain unavailable. Move into the blank future area and confirm the candle tooltip disappears instead of showing stale or invented values.
3. Zoom with the wheel at several pointer positions; verify the anchor away from boundaries. Drag in both directions and use Left/Right, `+`, `-`, and `End` with the Canvas focused. Compare an unchanged candle before, during, and after a drag: its height and width must stay fixed, the price/volume ranges must remain fixed after release, and retained UTC tick labels must move with their bars without changing timestamp. Pan toward newer data until the latest candle is centered; confirm further panning stops there and extra blank space does not increase tick density. Zoom, **Latest**, and `End` must refit the vertical ranges; **Latest** and `End` must also restore approximately 20% right spacing. Test short histories separately because the zero lower bound can limit placement.
4. Load older history manually and by navigating near the left edge. Check the count, timestamp anchor, stable time labels, request serialization, and end-of-history behavior. A pan's locked vertical ranges must survive loading. Indicator changes from an older EMA seed are expected.
5. Start replay and observe a current-bar replacement followed by appended bars. Confirm the chosen right spacing survives appends and replacement alone does not move the view. After panning, ranges must stay locked while prices and volume continue updating; any out-of-range values must be clipped within their own pane until refitted. Pause and verify emissions stop; resume and verify the sequence continues. Pan away from the latest edge during replay and confirm the view stays there until **Latest** or `End`.
6. Add/remove MA, EMA, Volume, RSI, and MACD independently; check legends, pane space, tooltip content, and settings restoration when re-added. Change one indicator's parameters/style and confirm the others stay unchanged, including RSI levels and MACD signal/histogram colors. With all four panes present, drag each adjacent divider and check its keyboard/reset actions, shared horizontal alignment, and clipping; remove a pane and confirm the dividers update. Resize the window without an intermediate cleared frame. Resizing preserves locked ranges; period/presence changes refit vertical ranges without moving the horizontal viewport.
7. Switch between **English** and **简体中文** while paused after a pan and indicator toggle. Check controls, sample labels, OHLC/tooltip text, Canvas volume labels, status, document title/language/description, and accessibility labels. Loaded candles, viewport, locked scales, and indicator visibility must remain unchanged. Numbers and dates must use the selected locale while time stays UTC. Repeat during replay and an outstanding history request; progress must continue without duplicated subscriptions, restarted requests, or stale-language completion messages.
8. Refresh after an explicit language selection and confirm it is retained. In a fresh browser profile, check preferred-language detection and English fallback. With preference storage blocked, confirm startup and switching still work. At a narrow viewport, check both languages for clipped controls, overlapping text, and an accessible language selector.
9. Exercise an isolated startup failure, such as blocking the Wasm request, and confirm a visible localized error instead of an unexplained blank chart. Change language while the error is visible and check the message updates; retain the original diagnostic in the console. Also check a failed history request and its retry state. Restore the request and reload successfully.
10. Choose minute, hour, day, week, and month periods; verify labels, OHLCV, UTC boundaries, indicator recalculation, and partial-bucket state. Initially the monthly fixture contains 49 bars. Switch rapidly while loading history and during replay; stale results must not overwrite the chosen period, the simulated clock must continue, and a running replay must resume after loading. Indicator visibility is preserved. Refresh to check an explicit period preference.
11. Click a candle body/wick to reveal the series' center handles, then click a handle to open settings; a drag reaching 4 CSS pixels must not open them. Check blank-click/`Esc` deselection and the title/`Enter` fallback. In **Symbol**, test independent body/border/wick visibility and rising/falling colors, plus solid/hollow candles. In **Canvas**, test themes, background/grid colors, grid, and last-price visibility. **Apply** commits the draft; **Cancel**, close, and `Esc` discard it, including theme/reset changes. Applied settings must preserve data, pan ranges, indicator settings, and replay. Check version 1/2 migration to version 3 preserves custom colors. Collapse/reopen the watchlist sidebar and check both languages at 1280×720 and 360px width for usable controls and a visible chart.
12. Create all nine drawing kinds, select their edges/handles, drag bodies and endpoints, modify styles, lock/unlock, and delete. A locked object remains selectable but cannot move or be deleted. Verify `Esc` cancels unfinished edits, each complete drag is one undo step, and undo/redo restores geometry and styles. Pan, zoom, resize, prepend history, and run replay: anchors must stay on their data coordinates. Future blank space and the volume pane must reject new anchors. Verify both ray directions, horizontal rays extending only rightward, vertical lines clipped to price, coincident/offscreen anchors, and selectable extensions after anchors leave the viewport. Check copied stroke buffers and all four price transforms/inversion. Switch languages with a tool active and verify its category, label, and selected state.
13. Switch periods and return to check drawing isolation. Reload to check valid geometry restoration without undo/selection. Check settings and drawing behavior with unavailable storage and malformed local documents in an isolated fixture; do not overwrite a user's browser data. Unknown versions and mismatched instruments/scales must not load incompatible drawings. Confirm the 256-object limit has a visible state and remains undoable through supported edits.
14. Inspect console and network errors after the complete flow, distinguishing deliberately injected failures from unexpected errors. Check teardown and browser back/forward behavior separately; a single screenshot cannot validate lifecycle cleanup.

Touch/pinch behavior, screen-reader usability, long-running stream stability, purchased feeds, reconnects, and a Chrome/Firefox/Safari compatibility matrix require separate verification. Do not describe them as supported merely because desktop pointer input works.

For baseline presentation, verify first-visible/fixed references, straight/step paths, independent colors, scale inversion, single-point and out-of-range references, and unfilled future whitespace. In the browser, check apply/cancel, rejection of an empty fixed price, selecting the line/fill and reopening settings through a handle or Enter. Reload and change language to check version 1 migration and version 2 restoration; keep existing indicators, drawings and viewport unchanged when switching series types.

For pane arrangement, move Price below an auxiliary pane and verify header, drawings, ticks and dividers follow it. Maximize RSI/MACD, pan, restore, and confirm shared time and retained proportions; remove the maximized study and confirm the remaining panes return. Reload to retain order but clear maximization. Repeat labels/state feedback in both languages and check no hidden price controls accept input.

For Fibonacci retracements, check 0/1 endpoints, reversal, linear versus logarithmic interpolation, narrow high-price precision, axis inversion, disabled levels, extension hit testing and copied buffers. Edit a ratio, blur or press Enter, then reload; the committed value must persist. Reject invalid numbers without changing the object. Add/remove levels, modify one object's styles, lock/unlock, undo/redo and switch language. Check clipping with reordered/hidden price panes, crowded label omission, and that the settings dialog's Close action remains visible while scrolling.

Touch navigation checks use the real Wasm bridge to verify simultaneous separation/midpoint changes, range locks, threshold/no-op behavior, degenerate spacing, release flushing, third-contact draining and cancellation on resize. Controller tests simulate contacts; they do not establish browser pointer-capture ordering or physical-device usability. On touch hardware, test one-finger selection/pan and drawing, add a second contact during each, pinch across different panes, release either contact first, add a third, interrupt with period/size changes, and confirm no accidental selection, drawing commit or jump. Verify desktop mouse, wheel and axis behavior separately. Record device, OS and browser before claiming touch compatibility.

## Measurements

The benchmark also projects 256 Fibonacci objects with 24 enabled levels each against 100,000 retained bars and a 1,400×750 plot. It reports 31 samples of 30 operations after 10 warm-up samples, including bridge validation, marshaling and copied level output; it excludes Canvas rendering and interaction latency.

Run `npm run benchmark` after building Wasm. Its JSON output describes 100,000 retained bars, indicator periods 20 and 500, and a 1,400-CSS-pixel plot: the requested 2,000 slots clamp to about 233.33, producing 234 projected rows. Workloads include snapshots, 2,500-bar prepends, final-bar revisions through the bridge and prepacked numeric input, frames, 256 drawing projections, and pointer conversion. A separate extension workload projects 256 evenly mixed vertical lines, rays, extended lines, and horizontal rays, including both anchor and clipped-stroke copies. It reports runtime/OS/CPU and artifact metadata, actual load, and median/p95 over 31 samples of mean milliseconds per operation; setup is untimed. It measures Node-hosted Wasm and bridge CPU work, excluding Canvas, network, browser compositing, input latency, and displayed frame rate. Inspect the script and compare identical loads and measurement boundaries.

The browser's **Frame** metric is a rolling mean of up to 90 redraws on that device. It includes core geometry, Canvas command submission, and selected-candle DOM updates. It excludes presentation/compositing and is not an FPS or end-to-end latency measurement. Its tooltip states that scope.

For browser performance work, record hardware, OS, browser version, viewport, device-pixel ratio, retained and visible bar counts, drawing count, selected period, update frequency, build mode, warm-up, sample count, and the precise measured boundary. Separate initial load, cold/cached period aggregation, history prepend, latest-bar updates, pointer-only redraws, drawing edits, zoom, and pan. Use browser performance traces when attributing time to layout, rendering, garbage collection, or dropped frames.

Compare identical fixtures and workloads before claiming improvement over another build or product. Keep raw measurements in ignored `measurements/` or outside the repository, and include the meaningful environment and result in the review. No performance threshold or competitor superiority claim is implied by this checklist.
